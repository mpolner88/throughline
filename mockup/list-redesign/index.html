spec §3

Three tabs, one list

Every task the extractor finds lands in exactly one of today, this week, or later. The app opens on today. Tabs carry a count, and a short-lived +n after a note is processed so you can see where things went without leaving today.

today
Due today, said "today", "this morning", "before lunch", or carried over from an earlier day.
this week
Due on a named day within the current Mon–Sun week, or said "this week", "by Friday".
later
No date, or a date past this week. Includes "sometime", "eventually", "next week".
spec §4

The second note adds to the list

A new recording never replaces what is on screen. Its tasks merge into the same list, deduplicated by normalised text, and each tab re-sorts itself. Order within a tab is fixed and predictable:

today
Carried-over first, then priority, then the order you said them.
this week
Due date ascending, then priority, then spoken order.
later
Newest note first, then spoken order.

Each row keeps a small source label (which note, what time) so the trail back to the recording is one tap.

spec §5

Clearing

Tap the circle. The item drops into a done group at the foot of the same tab with an undo link, so a mis-tap costs nothing. Done items leave the tab at the next day boundary and stay in the note and in the agent's memory as completed.

Why "unfinished from last night" looks wrong today

Both lines came from a note recorded this morning. The block collects tomorrow_todos from every cached note with no date check, so anything you said "tomorrow" about appears immediately, labelled as last night, and never leaves.

The replacement is not a fixed block. Carried-over items are ordinary today rows with a from yesterday marker, and "tomorrow" items go to the this-week tab dated tomorrow, which becomes today overnight.

spec §6

Most important vs to-dos

Today the note detail shows two overlapping lists. "Most important" is built by concatenating priorities, high-priority to-dos, tomorrow to-dos, intentions and accomplishments, then falling back to the summary. So the same sentence shows twice, and sometimes a thing you already did sits in a checkbox list.

Proposal: the home list holds tasks only. Priority is a property of a task, shown as ordering and a quiet mark, not a second list. In the note detail, the section is renamed worth remembering and holds only non-task takeaways (decisions, constraints, context) so the two sections never share a line.

spec §7

Saved confirmation

Press record above and stop it to see the sequence. Saved is now a held state: primary weight, a filled tick, a thin bar that drains over 2.6 seconds so the hold is visible, and a haptic on device. It fires the moment the upload lands, not after processing, and the tab counters animate when the tasks arrive.

In the current build "saved" is a 14 px secondary label that appears only after "translating" finishes and then stays on screen until the next recording.
