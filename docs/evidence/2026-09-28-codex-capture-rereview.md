## Coverage and resolved revision-1 concerns

- **Data/API items 1–9:** owner-scoped reservation, immutable payload/time metadata, zero-byte rejection, user-session-only uploads, conditional finalization, cross-account isolation, additive old-client/JSON/demo compatibility and service-only RLS are appropriate requirements. C1/C4/C6 qualify the remaining lifecycle/privacy promises. None exists as implemented capture behavior yet.
- **Invariants 1–10:** durable pre-record allocation; checked finalization before success feedback; stored validated receipt before local audio deletion; independent recorder availability; one tray/list representation; immutable owner and stale-work rejection; no processing restart; truthful copy; accepted Home/sign-in appearance; and content-safe measurement are accepted. C1/C2/C3/C4 reconcile exceptions and ordering rather than weakening those invariants.
- **Authentication:** keeping credentials on offline refresh, sign-in-required on actual rejection, and matching-owner resume resolve B4. Implementation must epoch-check refresh success AND error, sign-in completion, requests and timers; prevent a stale refresh from restoring/clearing the next account's session; isolate cached notes during account changes; and reuse sign-in appearance with context-aware completion instead of rerunning onboarding. These are obligations under revision 2's isolation rule, not approval to redesign onboarding.
- **Behavioral checks 1–21:** offline/restart, lost receipt, concurrent recordings, permission, overflow, truthful sign-out counts, single representation, processing timeout, same/different-account auth, interruption, storage and server failure injection provide a useful matrix. C1–C6 add the missing adversarial cases. Auth refresh success/error races, local intent-write failure, receipt validation after audio retention, cross-owner error non-disclosure, and account deletion races need explicit automated coverage. Physical-device checks remain unrun.
- **Event separation:** accept distinct attempt failure, unknown acknowledgement, discard and terminal processing outcomes. The session funnel is not a cross-session recovery rate. Before reporting one, Codex must define per-capture saved/discarded/lost/pending denominators, observation window, cohorts, coverage and private deduplication in `product/metrics.md`. That file is unchanged in this review. Counts without identities and honest coverage remain the boundary.
- **Rollback:** preserving the capture store and draining queue while reverting presentation is correct; plain installation of build 2026082801 would strand pending captures. A later rollback target must be a newly verified compatible build, and server acceptance/tombstones must survive while capture-capable clients remain. No rollback or delivery is performed here.
- **A1 disclosure:** local durability adds no provider; retention, file-token/digest metadata, deletion-failure behavior and backup exclusion still need a final behavior-to-policy/manifest comparison before release. Do not treat a digest as automatically non-sensitive. Approved policy bytes remain unchanged; any necessary wording goes to Mike. R8 is a separate ordinary-inference permission decision.
- **Visual inspection:** Codex inspected the supplied accessibility sign-in at 375×667, unknown-result discard, and other-account-row PNGs. They are synthetic mock references, not native device evidence. This is not a new design selection or a complete accessibility pass.
